# ADR-0006: RAG (not fine-tuning) for the AI assistant

**Status:** Accepted

## Context
The assistant must answer questions about *arbitrary, previously-unseen* repositories,
grounded in the actual code, with verifiable references — on free infrastructure.

## Decision
Use **Retrieval-Augmented Generation**: chunk + embed each repo's code into a vector store,
retrieve top-k relevant chunks per question, and prompt a general LLM with that context.
Return numbered **citations** to the source.

## Alternatives considered
- **Fine-tuning a model per repo** — expensive, slow, needs training data, and goes stale on
  every code change. Infeasible for on-demand arbitrary repos.
- **Stuffing the whole repo into the prompt** — exceeds context limits and is costly.
- **Keyword search only** — misses semantic matches ("where is auth handled?").

## Consequences
- (+) Works on any repo immediately after indexing; no training.
- (+) Grounded + cited answers → trustworthy and verifiable.
- (+) Updating knowledge = re-index (cheap) vs. re-train.
- (−) Answer quality is bounded by retrieval quality (chunking + embedding model).
- (−) Free-tier embedding model (MiniLM, 384-dim) and LLM rate limits cap quality/throughput.
- (−) No re-ranking step yet → mitigated by guaranteeing slots for user-tagged files.
